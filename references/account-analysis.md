# 账号分析流程

## 1. 核对账号与材料范围

通过实际主页核对平台、名称、链接、简介、置顶和可见体量；只有截图则标为截图诊断。数字ID不清楚对应平台时仅补问这一缺口；可搜索核对时先做核对。

近期内容通常先看近30天可获取样本，用户给定时间窗时替换。主页笔记少则做起步期诊断，保留实际样本数；不假装取得完整历史。

每条样本记录标题、详情链接、原始发布日期、观察日期、可见互动、内容形态、主题、正文/封面读取状态。分开标注置顶样本、近期高响应样本和同账号中可比较的普通样本。

## 2. 先解释账号成立的理由

从可见材料回答：

- 人设/身份：账号声称或展示什么经验、角色和资源？哪些能核验？
- 面向谁：内容持续解决谁的什么具体问题？评论中有哪些需求证据？
- 承诺与证明：简介、置顶和代表作是否让新访客知道为什么关注？
- 内容主线：可归为哪些稳定主题？各主题如何服务同一受众？
- 承接：商品、课程、咨询、商务合作、私域或其他入口怎样与内容关联？

不根据少量用户名推定整个人群画像；“可能吸引企业主”的解释要连到业务问题、案例证据和公开承接入口，而不是写成已经获得某类客户。

## 3. 比较内容，而不只列热度榜

按标题承诺、实际封面、开头、内容结构、案例/数据证明、可执行价值、结束动作和评论需求比较代表作。关注：

- 哪些题材与表达反复有效，哪些只出现过一次高热？
- 重复封面/标题是否是已有高热结构的复用？复用后是否仍有明显波动？
- 标题承诺与正文是否匹配，受众是否能在开头确认与自己有关？
- 置顶是否承担介绍、信任证明或行动入口？

尽量比较发布时长、格式和账号背景相近的样本；新发帖子和已累积一年的帖子不直接按累计赞数评价优劣。不可见曝光、点击或私信时，把诊断写为待验证假设。

## 4. 有足够历史再分析演化

用户要求起步阶段时，实际寻找可获取的早期帖子与时间节点。每阶段写“时间范围＋代表内容链接＋内容/承接变化＋保留/放弃什么”；证据不足时缩小范围或说明早期资料缺口，不倒推虚构成长故事。

区分内容策略变化和观察到的公开表现；没有中间数据时不把它们写成确定因果。

## 5. 聚合为用户能执行的方案

先提炼最有证据的一条整体策略，再给用户当前能迁移的模块：

```text
可见做法 → 为什么可能有效 → 迁移所需条件 → 用户可以怎样试 → 观察什么结果
```

内容规划包含栏目目的、目标问题、证据来源、内容形式、承接方式和测试选题。避免仅给一堆标题；也不固定每个账号必须同样的栏目数量、内容比例或更新频率。

优先安排一个小规模实验，例如同一问题的两种开头、相近主题的案例型/清单型表达、调整置顶承接。评价指标从用户可取得的数据中选择，不能承诺涨粉或成交。

## 6. 默认成品

一段核心判断 → 材料范围 → 定位与受众 → 内容/标题/封面证据 → 引流与承接 → 最主要差距 → 可迁移动作。用户要求深度报告时增加历史演化与横向矩阵；简单主页问题直接交付重点结论。
